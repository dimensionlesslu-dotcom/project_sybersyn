# Project Cybersyn — 分级闭环控制系统

> 符号 e/k/τ/σ/ε/F 在文本/代码任务中是隐喻，非可测标量——以"定性代理"为准，数值仅为可调经验默认。

> English version: [SKILL.en.md](SKILL.en.md) · 英文版见 [SKILL.en.md](SKILL.en.md)

---

## 宿主规则优先

本 Skill 只负责组织任务闭环，**不覆盖**宿主 Agent 的系统规则、开发者规则、工具权限、安全策略、代码编辑规范和用户最新指令。若本 Skill 与宿主规则冲突，**以宿主规则为准**。

## 可见性规则

哪些流程内容展示给用户，哪些只在内部使用：

| 层级 | 展示规则 |
|------|----------|
| L1 | **不展示闭环术语**，仅在最终回答中简短说明"已按需求核对"。 |
| L2 | 仅在测试失败、批量风险或用户要求时展示简版日志。 |
| L3 | 展示关键决策点：复杂度判定、主要偏差类型、是否触发二阶审计、最终验收结果。 |
| L4 | 显式展示假设、分歧、用户待决问题、研讨厅结论。 |

用户明确要求"按 Cybersyn/闭环/控制论流程执行"时，可提高一档可见性。

## 0 复杂度自检 → 路由

| 层级 | 判定（可计数） | 示例 |
|---|---|---|
| L1 简单 | ≤2 文件/模块，无跨模块依赖，需求明确 | 单函数改、段落润色 |
| L2 简单巨 | 大量**同质**项目，无跨子系统协调 | 批量重命名、大规模测试 |
| L3 复杂巨 | ≥3 **异构**模块互有依赖，或需求含隐含假设 | 多模块重构、章节写作 |
| L4 开放复杂巨 | 需求/环境持续变，需多轮定性讨论才能厘清目标 | 创业、研究方向、政策 |

- **L1 极简路径**：计划一句 → 改 → 对照验收项查 → 交付门；不创建状态文件、不启动 subagent，也不因 Skill 流程增加对话轮次。
- **L1/L2**：使用最小闭环和第 4 节交付门，关闭正反馈，不默认填写 VSM。**L3/L4**：按需使用四分类和环境检测，但只有通过第 5 节审计门或用户明确要求时才启用审计 subagent。
- **L3/L4 优先分解**：升级研讨厅前，优先尝试把任务分解为若干可独立闭环的 L1/L2 子任务；只有当子任务之间的接口、目标或假设本身产生冲突时，才进入研讨厅。
- **准入**：每个核心风险点至少一种纠错策略；无方案者标"死区"（不进常规修正）。全无应对则禁止执行。

## 1 量 → 定性代理

### 通用代理

| 符号 | 代理（以此为准） |
|---|---|
| r(t) | 需求 + 验收清单（功能/质量/约束）+ 核心假设 |
| y(t) | 本轮实际产物 |
| e(t) | 缺失·多余·错误 三项清单 |
| k | 干预强度：微调 / 局部重写 / 整体重构 |
| 收敛 | RequirementEvidence 逐项 passed、无 unverified、无 B/C/D 或 high/medium 残留 |
| τ | 默认≈0，仅外部调用/长仿真时按"几轮拿到反馈"计 |

### 代码任务代理

| 符号 | 代码任务代理 |
|---|---|
| r(t) | 用户需求 + 测试/类型检查/lint + 不破坏既有行为 |
| y(t) | 当前 diff + 命令输出 + 测试结果 |
| e(t) | 未满足需求、失败测试、回归、风格/约束违背 |
| k | 小补丁 / 局部重构 / 跨模块重构 |
| 收敛 | 需求满足且相关验证通过，或无法验证时风险已说明 |

经验默认（可调）：Nmax — L1=2 / L2=3 / L3=5 / L4 不限；二阶审计每 m=3 轮（L1 放宽至 5）。

## 2 闭环六阶段

**计划→测试₁→反馈→修改→测试₂→输出**。不赌计划完美，赌迭代自校正。

1. **计划**：写 r(t) 验收清单 + 核心假设（待二阶审计挑战）+ 风险应对/死区；VSM 仅在需要时从参考材料载入。
2. **测试₁**：执行最小可行步骤，捕获 y(t)，**只记录不判断**（治"没看清就改"）。
3. **反馈**：算 e(t)，判类型（第 3 节）。**若偏差无法归类、目标疑似错误但 Agent 无权改目标、验证手段不可得、或继续修改会扩大风险，立即触发向人移交闸。**
4. **修改**：A→调参（精度不足增 k，引入新问题降 k）；C/D→不调参，按第 3 节；正反馈加速→**仅当 r(t) 最近经二阶审计确认才放行**（防自信冲向错目标），L1/L2 不开。单参数隔离**仅在因果不清时**用。
5. **测试₂**：比 e₂ vs e₁；(L4) 环境漂移超阈则重设 r(t)。判决：收敛 / 继续 / 超 Nmax→移交 / 环境失配→重启。
6. **输出+归档**：记收敛轮次、k、偏差类型分布。连续同类偏差＝结构性问题（改结构，写入下阶段）。跨会话归档为理想目标，单会话优先。

## 3 偏差四分类（核心，不可跨类套用；D 不能当 A 修）

| 类型 | 判定 | 响应 |
|---|---|---|
| A 执行偏差 | 方向对、细节未达标 | 常规调参（路径 A） |
| B 测量偏差 | 重复测量不一致 | **冻结执行**，先校准验证手段；误差≥修正精度禁止改 |
| C 环境漂移 | 偏差稳定但非执行所致；核心假设被新输入否定 | 暂停，重设 r(t)（触发二阶审计） |
| D 涌现偏差 | 各模块独立都过、集成异常 | **退出一阶回路**，回定性假设层；L3/L4 升研讨厅 |

## 4 交付验收门（交付前必过；L1 只跑①）

```
① 执行偏移：验收清单逐条核对——缺失?多余?错误? 应为空；无类型 B/D 残留
② 环境漂移：外部约束/资源/需求是否已变? 变则产物须仍满足新环境
③ 目标漂移：r(t) 核心假设是否仍成立且最近复核过? 否则回二阶审计，不交付
```

### 验收未通过时的输出

验收未通过时，必须输出以下四项：

1. **当前最佳产物**在哪里/是什么。
2. **未通过的验收项**（逐条列出）。
3. **偏差类型** A/B/C/D（每项对应）。
4. **建议下一步**：继续修改 / 重设目标 / 校准验证 / 请用户决策。

### RequirementEvidence 与命令边界

每个 requirement 都必须有独立账本项：`passed | failed | unverified | blocked`、可定位的
`test | inspection | source | user-confirmation` 证据，以及可同时存在的 A/B/C/D 偏差。
`unverified` 不等于 `passed`；关键词命中和模板预测只能是 candidate/假设，不能作为收敛证据。

`test_cmd` 默认只是待执行建议。只有宿主 Agent 明确授权、命令来源被标记为可信、且命令
通过受限执行器检查时才可运行；禁止 shell 控制符、管道和来自导入状态/网页的隐式执行。
命令、工作目录、退出码和截断后的输出必须进入证据记录。

## 5 二阶审计（质疑目标本身）

触发：每 m 轮，或——同类偏差连续 2 轮未消 / 偏差 A·B 突变 C·D / 过半 Nmax 未收敛 / 环境可见变化。

```
1 r(t) 假设从哪来? 最近验证过吗? 若 r(t) 本身错，偏差分析还成立吗?
2 我是否只选了支持先验的测量方式、回避了不想看的区域?
3 这是参数误差还是结构问题? 需换执行策略形状/增大多样性吗?
4 (按需) 实际在做的 vs 声称要做的，差距持续则改行为还是改声明?(POSIWID)
```

结论→继续微调 / 重设 r(t) / 重构策略 / 升研讨厅。**确认 r(t) 后才许开正反馈加速。**

审计 subagent（`assumption-auditor`）默认只读，不修改仓库、状态或外部系统，不直接联系用户，
也不读取主 Agent 的预期答案、诊断、拟议修复或其他审计输出。缺证据时只能提出最低成本区分性测试。

多视角验证通过 `tools/validation_prompt_assembler.py` 组装 PromptPacket；组装器不启动 subagent。
默认只选择一个风险最相关的视角（B/unverified→`measurement`、跨模块/D→`integration-regression`、
目标冲突→`goal-spec`、环境变化→`environment`）。三视角并行仅在用户明确请求或第 5 节预算审计门
通过时开启；在新评测证明稳定净收益前，不把它升级为默认路径，并保留各视角的独立输入边界。

### 审计启用与增量总成本门

默认采用单流程：用户未明确要求审计且未声明成本阈值时，不启动审计 subagent，
不组装多角度 PromptPacket；运行 smoke、与修改范围直接相关的 unit、integration、
lint、type-check 和证据核对，由当前 Agent 分析结果。证据不足时禁止宣称完成，
但不得静默扩大审计。

自动开启多角度审计必须同时满足：用户声明预算、宿主提供有效且当前的价格记录、
预计增量总成本不超过预算、任务不是 L1，且未超过 subagent 调用和上下文上限。
预计成本为：

```text
预计增量总成本 = Σ(
    预计输入 Token × 输入单价
  + 预计输出 Token × 输出单价
  + 非 Token 工具费用
)
```

用户明确提出“审计、交叉验证、多角度检查、派 subagent、反问假设、红队测试、
独立复核”等意图时，直接按对应审计执行，但仍遵守用户总预算和调用上限；若需求
与预算冲突，报告冲突，不静默取消或扩张审计。

不得虚构价格。价格由宿主提供并记录：

```json
{
  "model": "model-id",
  "input_price_per_million": 0,
  "output_price_per_million": 0,
  "price_source": "host-runtime",
  "observed_at": "ISO-8601"
}
```

价格或预算未知时不自动审计；使用单流程测试，高风险任务可提示用户是否授权审计。
单价门不能替代总成本门；若用户坚持使用单价判断，还必须同时设置预计 Token 和
subagent 调用上限。

### 有界复用扫描

完成需求、约束和非目标分析后，在设计或编码前，对绿地项目、L3/L4 任务及通用基础
能力，在用户允许联网时执行有界复用扫描。L1、局部修复、离线任务和高度专有需求
默认跳过。仅搜索相关来源，最多保留 3–5 个候选，并按功能、许可证、安全性、维护
状态和集成总成本比较，选择 `adopt`、`wrap`、`fork`、`reference` 或 `build` 之一。
不得仅凭流行度采用项目；未经授权不得安装或执行第三方代码，并记录候选、最终决策
和被拒绝的替代方案。

## 6 下一阶段计划生成（里程碑交接）

```
① 核心假设逐条标【已验证→固化为下阶段前提 / 已推翻→下阶段须重设的目标 / 未触及→下阶段首测项】
② 残留死区→下阶段最高优先级（源于能力缺口则先补能力）
③ 学习归档若"总是同类偏差"→不是调参，下阶段直接改执行结构
```
产出下阶段 r(t) 清单 + 优先级 + 复用初始参数后，回第 0 节重做自检。

## 7 研讨厅（L4 / 持续不收敛）

人-机循环、以人为主。五原则：
1. 对同一对象建 ≥3 个**不同结构**模型，预测分歧本身即信号。
2. 不追求唯一正确模型。
3. 机器做定量推演，人做定性判断。
4. 每轮显式声明假设集，下轮先挑战其一（衔接二阶审计）。
5. 收敛＝各视角不再产生新的定性分歧（非 e→0）。

收敛后下沉为新 r(t)/策略，任务降级回常规闭环（接第 6 节）。

## 8 安全与边界

- **Nmax**：超过即停——**停＝上报+请人介入**（给当前最佳结果+不收敛原因+待决选项），非放弃。
- **时滞**：连续两轮偏差同向增大即近临界，**禁止增大 k**。
- **F₂ 精度**：验证误差≥修正精度，先校准再改（类型 B）。
- **向人移交闸**：Nmax 未收敛 / r(t) 疑错但无权改目标 / 落入死区 / 环境使需求失效 / 自主对象持续偏离预期 / 偏差无法归类——任一即把不确定性抛回用户。
- **结构耦合**：自主对象（用户/团队/agent）的控制信号是扰动非指令——扰动→观察其结构响应→适配，胜过多轮硬指令。
- **非线性**：出现饱和/死区/磁滞时线性公式失效，重新建模。

## 9 配套工具（可选，L2+ 推荐）

若环境可执行 Python，可用 `tools/` 下的脚本把闭环状态持久化（跨轮/跨会话），替代纯上下文记忆：

```
complexity_classify.py --task "..." --files ...   # 第0节：复杂度判定
cybersyn_state.py init --level L3 --task "..."    # 初始化状态文件
cybersyn_state.py next-round                       # 每轮开始时推进（自动执行 Nmax 闸）
cybersyn_state.py update --stage feedback --data . # 记录 e(t) 与偏差类型
convergence_check.py --state ... --energy          # 测试₂：收敛判定
audit_trigger.py --state ... --auto-conclude       # 二阶审计触发与结论推荐
validation_prompt_assembler.py --task "..."       # 只组装只读 PromptPacket，不启动 subagent
handoff_report.py --state ...                      # 向人移交时生成报告
```

工具仅是状态载体：判定偏差类型、下审计结论仍由 Agent 负责。无 Python 环境时按第 10 节日志格式在上下文中记录即可。用法详见 `tools/README.md`，完整示例见 `examples/`。

## 10 迭代日志（L1 只填前 6 项）

```
[轮次 #n | L?]
计划 r(t)清单+核心假设; 风险应对/死区; VSM 按需载入
测试₁ y₁(只记录); (τ非零)反馈轮距
反馈 e₁=缺失·多余·错误; 类型 A/B/C/D
修改 路径 A/B(过r(t)审计?)/C·D; 改动; 单参隔离?(仅因果不清)
测试₂ e₂vs e₁; (L4)环境漂移; 判决:收敛✅/继续↩/超Nmax→移交❌/失配🔄
输出 [收敛时]最终偏差; 总轮次; 归档:同类偏差?结构性问题?
二阶 [每m轮] r(t)还成立?观察者偏见?需换结构?
```
